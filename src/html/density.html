Understanding Pixel Density

Modern displays pack different numbers of physical pixels into each CSS pixel. A device pixel ratio (DPR) of 2 means each CSS pixel is rendered using 2×2 physical pixels.

1× (Standard) 1 CSS px = 1 physical px
2× (Retina) 1 CSS px = 4 physical px
3× (Super) 1 CSS px = 9 physical px

The Q unit in unit.gl equals 1 CSS pixel at standard density. As density increases, Q units maintain their CSS size while using more physical pixels for sharper rendering.

Density Buckets

unit.gl uses Android's density bucket system for semantic targeting. Each bucket corresponds to a specific DPR and DPI range:

Bucket DPR DPI Common Devices
ldpi 0.75× 120 Legacy low-resolution displays
mdpi 1× (baseline) 160 Standard desktop monitors
hdpi 1.5× 240 Some laptops, older tablets
xhdpi 2× 320 Retina MacBooks, most phones/tablets
xxhdpi 3× 480 iPhone Pro, Samsung Galaxy S series
xxxhdpi 4× 640 Some Android flagships

Tip

You can also use semantic aliases: "standard" (1×), "retina" (2×), "super" (3×), and "ultra" (4×).

Functions

density($bucket)

Returns the DPR value for a density bucket name.

@use "unit.gl" as *; $dpr: density("xhdpi"); // 2 $dpr: density("retina"); // 2 (alias) $dpr: density("xxhdpi"); // 3

density_dpi($bucket)

Returns the DPI value for a density bucket.

$dpi: density_dpi("xhdpi"); // 320 $dpi: density_dpi("xxhdpi"); // 480

q_to_mm($q_value)

Converts Q units to physical millimeters. Based on the traditional Kyū unit where 1Q = 0.25mm.

$mm: q_to_mm(16); // 4mm $mm: q_to_mm(160); // 40mm (Q1 base unit) $mm: q_to_mm(320); // 80mm (Q2)

mm_to_q($mm_value)

Converts physical millimeters to Q units.

$q: mm_to_q(4); // 16 $q: mm_to_q(40); // 160 (Q1)

q_to_px($q_value, $dpr)

Converts Q units to physical screen pixels at a given DPR.

$px: q_to_px(16, 1); // 16 physical pixels $px: q_to_px(16, 2); // 32 physical pixels $px: q_to_px(16, "xhdpi"); // 32 physical pixels

q_to_pt($q_value)

Converts Q units to typographic points (1pt = 0.3528mm).

$pt: q_to_pt(16); // ~11.34pt $pt: q_to_pt(12); // ~8.5pt

density_suffix($bucket)

Returns the image resolution suffix for a density bucket.

$suffix: density_suffix("mdpi"); // "" (no suffix) $suffix: density_suffix("xhdpi"); // "@2x" $suffix: density_suffix("xxhdpi");// "@3x"

Mixins

display_density($min-dpr)

Applies styles at a minimum device pixel ratio.

@use "unit.gl" as *; // Target 2× displays and higher @include display_density(2) { .logo { background-image: url("logo@2x.png"); background-size: 100px 50px; } } // Target 3× displays and higher @include display_density(3) { .hero { background-image: url("hero@3x.jpg"); } }

display_bucket($bucket)

Applies styles for a specific density bucket using semantic names.

// Target retina (2×) displays @include display_bucket("xhdpi") { font-weight: 300; // Thinner fonts look better on retina } // Or use aliases @include display_bucket("retina") { border-width: 0.5px; }

display_standard()

Targets only standard (1×) density displays.

@include display_standard { // Fallback for non-retina displays .icon { background-image: url("icon.png"); } }

image_density($path, $ext, $densities)

Generates density-aware background images with automatic resolution switching.

.logo { @include image_density("/images/logo", "png", 1 2 3); } // Compiles to: .logo { background-image: url("/images/logo.png"); background-image: -webkit-image-set( url("/images/logo.png") 1x, url("/images/logo@2x.png") 2x, url("/images/logo@3x.png") 3x ); background-image: image-set( url("/images/logo.png") 1x, url("/images/logo@2x.png") 2x, url("/images/logo@3x.png") 3x ); }

display_print($min-dpi)

Targets print media with optional minimum resolution.

@include display_print { // All print styles .no-print { display: none; } } @include display_print(300) { // High-resolution print only (300dpi+) .photo { image-rendering: high-quality; } }

Runtime DPR Access

unit.gl automatically injects the device pixel ratio as a CSS custom property, enabling dynamic density-aware calculations in CSS:

/* Available CSS custom properties */ :root { --dpr: 2; /* Current device pixel ratio */ --dpr-inverse: 0.5; /* 1 / DPR for inverse calculations */ } /* Use in calculations */ .hairline { border-width: calc(1px * var(--dpr-inverse)); /* True 1px on any display */ } .icon { /* Scale based on density */ transform: scale(var(--dpr-inverse)); }

Note

The --dpr variable updates automatically when moving windows between displays with different densities.

Unified Q Format & Breakpoints

unit.gl unifies physical Q paper formats with digital breakpoints using a consistent 4× multiplier. This creates a seamless bridge between print and screen design.

1mm (physical) = 4px (CSS at 1× DPR)

Physical-to-Digital Mapping

Q paper formats map directly to responsive breakpoints. Portrait widths serve mobile devices, landscape widths serve desktop:

Breakpoint Q Format Orientation Width (mm) ×4 = px Device Category
us Q07 Portrait 60mm 240px Compact / Fold devices
ss Q06 Portrait 90mm 360px Phones
xs Q05 Portrait 135mm 540px Large phones / Small tablets
sm Q04 Portrait 180mm 720px Tablets
md Q03 Landscape 360mm 1440px Laptops / Desktops
lg Q02 Landscape 540mm 2160px QHD / Ultrawide
xl Q01 Landscape 720mm 2880px 4K displays
ul Q00 Landscape 1080mm 4320px 5K+ displays

Conversion Functions

@use "unit.gl" as *; // Physical to digital $width: mm_to_px(90); // 360px (Q06 portrait) $width: mm_to_px(360); // 1440px (Q03 landscape) // Digital to physical $mm: px_to_mm(1440px); // 360mm // Density-adjusted $physical_px: breakpoint_for_density(md, 2); // 2880 physical pixels

Combined Viewport + Density Queries

The media_density mixin targets specific breakpoints AND densities together:

// Target phones (ss) with retina displays @include media_density(ss, 2) { font-size: 14px; font-weight: 300; // Thinner weights on retina } // Target tablets (sm) with any density @include media_density(sm) { max-width: 600px; } // Target laptops (md) with 3× displays @include media_density(md, 3) { border-width: 0.333px; // True 1px hairline }

Q Format Semantic Targeting

Use media_format to target Q paper sizes directly:

// Target Q06 portrait devices (phones) @include media_format(q06p) { padding: q(16); } // Target Q03 landscape devices (laptops) with retina @include media_format(q03l, 2) { font-weight: 300; } // Target Q01 landscape (4K) with any density @include media_format(q01l) { max-width: q(1400); }

Why 4× Multiplier?

The 4× multiplier (1mm = 4px) bridges the gap between the traditional print standard (96dpi ≈ 3.78 px/mm) and our Q unit system. This creates clean, round breakpoint values that align perfectly with the Q format paper dimensions.

Density-Aware Typography

High-density displays render CSS pixels using more physical pixels. For optimal readability, typography can be adjusted based on density.

fluid_type_density() Mixin

Extends fluid typography with density awareness. High-DPR screens get proportionally smaller text to maintain optical consistency:

html { // Base fluid type: 12px → 24px from 360px → 4320px viewport @include fluid_type_density(360px, 4320px, 12px, 24px); } // With custom density scale (default: 0.9 = 10% reduction per DPR step) html { @include fluid_type_density(360px, 4320px, 12px, 24px, 0.95); }

This generates:

  • 1× DPR: 12px → 24px fluid scaling
  • 2× DPR: 10.8px → 21.6px (×0.9)
  • 3× DPR: 9.72px → 19.44px (×0.81)

q_density() Function

Runtime density-aware Q units using the JavaScript-injected --dpr-inverse:

.element { font-size: q_density(16); // Scales with runtime DPR padding: q_density(8); line-height: q_density(24); } // Compiles to: .element { font-size: calc(1rem * var(--dpr-inverse, 1)); padding: calc(0.5rem * var(--dpr-inverse, 1)); line-height: calc(1.5rem * var(--dpr-inverse, 1)); }

scale_density() Functions

Retrieve typographic scale values adjusted for density:

// Compile-time density adjustment font-size: scale_density(7); // q(16) at 1× DPR font-size: scale_density(7, 2); // q(16) × 0.9 at 2× DPR font-size: scale_density(7, 3); // q(16) × 0.81 at 3× DPR // Runtime density adjustment (requires JS injection) font-size: scale_density_runtime(7); // Scales with --dpr-inverse

CSS Custom Properties

unit.gl provides density and breakpoint values as CSS custom properties for use in calculations:

:root { /* Density (JavaScript-injected) */ --dpr: 1; --dpr-inverse: 1; /* Density-adjusted grid */ --grid-unit: 0.5rem; /* q(8) */ --grid-unit-density: calc(var(--grid-unit) * var(--dpr-inverse)); /* Physical-to-digital multiplier */ --mm-to-px: 4; /* Q-format-derived breakpoints */ --bp-us: 240px; /* Q07 Portrait */ --bp-ss: 360px; /* Q06 Portrait */ --bp-xs: 540px; /* Q05 Portrait */ --bp-sm: 720px; /* Q04 Portrait */ --bp-md: 1440px; /* Q03 Landscape */ --bp-lg: 2160px; /* Q02 Landscape */ --bp-xl: 2880px; /* Q01 Landscape */ --bp-ul: 4320px; /* Q00 Landscape */ } /* Usage example */ .element { /* Density-aware spacing */ padding: var(--grid-unit-density); /* Container query using breakpoint */ max-width: var(--bp-md); }

Q Units & Physical Size

The Q unit provides a bridge between screen and print through its physical definition:

1Q = 0.25mm (physical) = 0.0625rem (CSS) ≈ 1px (at 16px base)

Screen vs Print

Q Value Physical Size CSS Size Physical Pixels (1×) Physical Pixels (2×)
1Q 0.25mm 0.0625rem 1 2
16Q 4mm 1rem 16 32
160Q (Q1) 40mm 10rem 160 320
320Q (Q2) 80mm 20rem 320 640

This unified system means you can design for screen and print using the same Q values. When printing, Q units map directly to physical millimeters. On screen, they adapt to the display's density while maintaining proportional relationships.

Best Practices

✓ Provide @2x assets minimum

Most modern devices are at least 2× density. Always provide @2x images; @3x is recommended for icons and logos.

✓ Use vector graphics when possible

SVG and icon fonts scale perfectly at any density. Reserve bitmap images for photos and complex graphics.

✓ Test on multiple densities

Use browser DevTools to simulate different DPRs. Chrome: Device Toolbar → DPR dropdown.

✓ Use image_density for backgrounds

The image_density mixin handles fallbacks and browser prefixes automatically.

✗ Don't assume 1× baseline

Standard 1× displays are increasingly rare. Design for 2× first, then optimize for other densities.

✗ Avoid density-dependent sizing

Let CSS pixels and Q units handle scaling. Only use physical pixel calculations for specific effects like hairline borders.
